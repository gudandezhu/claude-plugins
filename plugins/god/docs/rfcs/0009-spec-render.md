## 1. 背景

`skills/spec-review/SKILL.md` 已实现 D1-D4 4 维度评分（需求完整 / 用户视角 / GWT 可验证性 / 双向绑定）。但**评审者直接读 `spec.feature` Gherkin 原文**做评分：

- 评审者要脑补"哪条 REQ 覆盖哪个 SC"（D1）
- 评审者要脑补"哪个 SC 没在代码 / 测试里"（D4）
- 评审者要看完整 Gherkin 才知"哪些是 sad-path / intent"（D2 边界）
- 重复劳动：每次 spec 改完都重评一遍 D1-D4

**核心价值**：spec-render 把 `spec.feature` + `spec/sources.md` 翻译成**评审者视角的 checklist**（`review.md`），D1-D4 评分有自评草稿，评审者只需在草稿上修。

## 2. 目标

| # | 目标 | 验证 |
|---|---|---|
| 1 | 读 `spec.feature` + `spec/sources.md` + `spec/meta.json` 输出 `spec/review.md` | CLI 一行调用 |
| 2 | review.md 含 D1 需求完整性 checklist | 每 REQ → 覆盖 SC 一目了然 |
| 3 | review.md 含 D2 用户视角清单 | sad-path / intent 分类列表 |
| 4 | review.md 含 D3 GWT 可验证性 | Given/When/Then 字段非空机械检查 |
| 5 | review.md 含 D4 双向绑定矩阵 | SC → 代码 → 测试三方映射 |
| 6 | dry-run 模式可预览不写 | `--dry-run` 不写文件 |
| 7 | 与 spec-review skill 联动 | spec-review 阶段自动 render（避免重复）|

### 3.2 CLI 签名

```bash
# 生成 review.md
$ node spec/scripts/spec-render.js <项目目录>

# 预览
$ node spec/scripts/spec-render.js <项目目录> --dry-run

# 强制覆盖
$ node spec/scripts/spec-render.js <项目目录> --force
```

### 3.3 关键约束

| 约束 | 决定 |
|---|---|
| 输入 | `spec/spec.feature` + `spec/sources.md` + `spec/meta.json` |
| 输出 | `spec/review.md`（与 spec.feature 同目录）|
| 解析 spec.feature | 复用 dev-gen 的 `parseFeatureScenarios`（抽 lib 或 inline 复制）—— 当前选择 inline 复制保持独立可跑 |
| REQ 解析 | 从 `sources.md` 表格解析（"REQ-xxx \| 描述 \| ... \| 归属"）|
| 代码 / 测试扫描 | 复用 spec-validate.js 的 `#7 #8` 扫描逻辑（inline 复制）|
| 不读 spec-review | 评分草稿留空，由 spec-review skill 跑完回填 |
| 覆盖策略 | 默认询问（`--force` 跳过）|
| 失败回滚 | 写失败 → 自动恢复原 review.md |

### 3.4 与现有工具的关系

| 工具 | 关系 |
|---|---|
| `spec-validate.js` | spec-render **不重复**校验逻辑；只读 spec.feature 解析 + 扫描代码/测试（不报错，只列状态）|
| `spec-summary.js` | summary.md 给 OPC 看（签字用）；review.md 给评审者看（找 bug 用）。**两个产物并存，不合并**|
| `spec-review` skill | spec-review 跑前**先自动 render**（避免重复）；review.md 自评草稿是 spec-review 副产物 |
| `spec-cli.js` | 不联动（spec-render 不读 phase 状态）|

## 5. 反模式（明确不做）

- ❌ spec-render 写评分（**只写 checklist + 草稿占位**）—— 评分是 spec-review 的活
- ❌ spec-render 跑 spec-validate（**只读，不校验**）—— 校验是 spec-validate 的活
- ❌ spec-render 合并到 summary.md（**两个产物独立**）—— 用途不同
- ❌ spec-render 修 review.md 旧版 diff（**只覆盖**）—— 历史由 spec-archive 留
- ❌ 自动跑 spec-render 写 review.md（**必须显式**，spec-review 阶段可自动调）—— 避免污染
