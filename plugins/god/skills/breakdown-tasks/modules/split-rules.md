# 任务拆分规则

## 基础设施拆分路径

> 生成 INFRA 任务前，检查 tech-design.md 是否涉及以下场景。

**独立 INFRA 任务的条件**（满足任一即独立）：

| 条件 | 示例 | 任务内容 |
|------|------|----------|
| 数据库迁移 | 新表 DDL、字段变更 | DDL 脚本文件路径引用（不内联建表语句） |
| 引入新 SDK/依赖 | 银行直联 SDK、支付 SDK | 引入依赖坐标 groupId:artifactId + 配置类 + 初始化逻辑 + 连通性验证 |
| 被两个及以上 BE 任务共享的领域模型/DTO/VO | 多模块共用的 SupplierEntity | 类名 + 包路径 + 一句话职责 |
| 全局性基础设施 | 全局异常处理、拦截器、公共配置 | 类名 + 包路径 + 一句话职责 |

**内联到 BE 任务的条件**（不独立）：

| 条件 | 处理方式 |
|------|----------|
| 只被一个 BE 任务使用的 Entity/DTO/VO | 直接在该 BE 任务的"核心流程"中描述 |
| 单表对应的 Entity（只有一个 BE 任务操作该表） | 内联到该 BE 任务 |
| 仅被一个模块使用的工具类/配置项 | 内联到使用它的 BE 任务 |

**内容边界**：
- 除了引入配置需要配置类外，INFRA 不描述"代码怎么写"（字段映射、方法签名、SQL 骨架、VO 字段枚举）。代码归属 BE 任务。

**编号**：`INFRA-01`、`INFRA-02`...，排在所有 BE 任务之前。

## 后端拆分路径

> 生成后端任务前，必须先读取 tech-design.md，记录接口路径、业务流程、所有异常场景和状态码。

**默认规则：同一实体的全部 CRUD 接口合并为一个任务。**

一个任务包含该实体的全部接口的完整实现（model + controller + service + repository + test）。

示例：`BE-01 供应商管理（POST /suppliers, GET /suppliers, GET /suppliers/{id}, PUT /suppliers/{id}, DELETE /suppliers/{id}）`

**拆分条件**（满足**任一**才拆分，否则保持合并）：

| 条件 | 说明 |
|------|------|
| 单接口核心流程超过 10 个业务步骤（含分支逻辑） | 合并后超出 Agent 单 session 容量 |
| 接口分属不同微服务 | 微服务边界是天然拆分点 |
| 接口属于不同业务子域 | 各自有独立的事务边界和外部依赖（如：订单创建 vs 订单退款） |
| 部分接口需要前置基础设施 | 需要准备的接口与准备任务合并，其余接口独立 |

**编号**：`BE-01`、`BE-02`...，任务名称使用 `{实体名}{操作组}` 格式，如"供应商管理 CRUD"、"订单创建与查询"。

**内容要求**：
- 多接口任务的"新增接口"表格列出所有接口行
- 核心流程按接口分段描述，每个接口独立步骤链
- 验收标准覆盖所有接口的正向/异常/联动场景
- 从 tech-design.md 中提取待办项、不确定项、需对齐确认的枚举/配置，写入"前置确认项"区块作为阻塞项

## 前端拆分路径

> 生成前端任务前，必须先读取 UI 设计稿，逐区域记录页面元素，再对照 PRD 和 tech-design.md 梳理交互操作。

**规则：**
- **默认：一个页面 = 一个任务**，包含该页面下所有子组件、状态管理、交互逻辑、测试
- **公共组件独立条件**（三个条件**全部满足**才独立为前置任务）：
  1. 被两个及以上页面/任务使用
  2. 有独立的设计规格（不仅仅是简单封装）
  3. 独立开发/测试/验收比内联开发更有价值
- 不满足独立条件的公共组件（如只被一个页面使用的表格封装），内联到使用它的页面任务中
- 必须列出涉及的文件（修改/新增），标明文件路径和修改内容
- 从 tech-design.md / PRD 中提取待确认项，写入"前置确认项"区块作为阻塞项

---

## 前后端独立性原则

**前端任务与后端任务完全独立，互不依赖。** 前后端可并行开发，不允许建立任何形式的依赖关系。接口字段和路径通过 tech-design.md 对齐，而非任务依赖。

禁止出现以下依赖：
- FE 任务依赖 BE 任务完成（×）
- BE 任务依赖 FE 任务确认（×）
- phases 中强制 "后端 → 前端" 排序（×）

---

## 依赖类型说明

依赖仅存在于**同角色内部**，唯一例外是 INFRA → BE：

| 依赖类型 | 说明 | 示例 |
|---------|------|------|
| 基础设施依赖 | INFRA → BE | BE-01 依赖 INFRA-01（数据库表创建） |
| 功能依赖（后端内部） | 基础功能 → 衍生功能 | BE-02 依赖 BE-01（注册 → 登录） |
| 组件依赖（前端内部） | 公共组件 → 页面组件 | FE-02 依赖 FE-01（表格封装） |
| 跨迭代依赖（同角色内） | 前序迭代 → 当前迭代 | IT-02 的 BE-01 依赖 IT-01 全部 BE 完成 |
