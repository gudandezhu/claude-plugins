# TDD 铁律

**没有失败的测试，就不能写生产代码。** 先写了代码？删掉，从测试开始。

## RED-GREEN-REFACTOR 循环

每个功能点必须走完一个完整循环：

1. **RED** — 写一个失败测试，运行确认失败（不是报错，是功能未实现）
2. **GREEN** — 写最少的代码让测试通过，禁止添加额外功能或"顺便"改代码
3. **REFACTOR** — 清理代码，保持测试通过，不添加新行为

一个循环完成 → 立即提交。

## 测试要求

- 一个测试只测一种行为，名称清晰描述行为
- 优先用真实代码，避免 mock
- 每次必须**实际运行**确认红/绿，不能跳过
- 新增/修改代码覆盖率必须**90%**，依赖的中间件/数据必须mock

## 遇到 Bug

先写复现 bug 的失败测试，再走 RED-GREEN-REFACTOR。不要直接改代码。

## 前端（Vue/TS + Vitest）

```bash
npx vitest run src/views/__tests__/example.test.ts  # 单文件
npx vitest run                                       # 全部
```

## 后端（Java/Spring Boot + JUnit）
加载 `zcode:java-unit-test` skill编写单测代码
测试运行使用测试类的 main 方法或直接执行 JUnit 测试。

## 危险信号 — 立即停下

| 想法 | 行动 |
|------|------|
| "太简单不需要测试" | 写测试，只需 30 秒 |
| "先写代码再补测试" | 删掉代码，从测试开始 |
| "手动测过了" | 手动测试无法回归 |
| "就这一次跳过" | 停下，从测试开始 |

## 完成前确认

- [ ] 每个新功能有对应测试
- [ ] 每个测试先看到失败
- [ ] 只写了让测试通过的最小代码
- [ ] 所有测试通过，输出干净
