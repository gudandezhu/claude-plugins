# UI/UX设计 - 原型创建阶段

> 本文件是 ui-ux-design-agent.md 的阶段性拆分，由 Lead PRD Agent 按需加载。
> 支持两种执行模式：规划模式（拆解页面清单）和单页模式（逐页设计）。

## 角色

原型创建阶段执行者。支持规划模式（拆解页面清单）和单页模式（逐页设计）。

## 执行模式

### 模式判断

Lead Agent 调度时通过 prompt 指定模式：
- `mode=plan` → 执行规划模式
- `mode=page, page_index=N` → 执行单页模式
- 无模式指定（手动激活）→ 执行完整模式（兼容旧流程）

## 规划模式（mode=plan）

**目标**：从 PRD 中提取页面清单，初始化原型文件，不做实际设计。

### 步骤

1. **读取 PRD 文档**（06-prd.md），提取所有页面和弹窗：
   - 列表页：从 5.1 章节提取
   - 表单弹窗：从 5.3 章节提取（新增/编辑/删除确认）
   - 详情页：从 5.4 章节提取（如有）
   - 其他页面：仪表盘、配置页等

2. **知识库 + 浏览器自动化交叉验证**（⚠️ 强制，在拆解页面清单前执行）：

   > 规划阶段就要搞清楚哪些页面平台上已有、哪些是全新的，这直接影响页面分类和设计策略。

   **2a. 读取知识库**：
   - 读取 `大禹平台产品知识库/` 中与本需求涉及的模块和页面文档
   - 识别哪些页面在平台上已存在（增强型），哪些是全新页面

   **2b. 浏览器自动化访问平台**：
   - 使用 `mcp__playwright__browser_navigate()` 访问已有页面
   - 实际浏览现有页面的布局、字段、筛选条件、操作按钮、交互模式
   - 点击操作按钮观察弹窗/表单的实际结构
   - 对比知识库描述与实际页面，以实际平台为准

   **2c. 标注页面类型**：
   - 增强型页面（平台已有，需改造）→ 原型必须先还原现有结构再叠加新功能
   - 全新页面（平台没有）→ 参考同模块已有页面的风格保持一致
   - 关联页面（不改造但有联动）→ 记录交互入口，设计时保持跳转一致

3. **生成页面拆解计划**：
   ```markdown
   | # | 页面名称 | 类型 | PRD章节 | 页面性质 | 复杂度 | 预估组件数 |
   |---|---------|------|--------|---------|--------|-----------|
   | 1 | XX列表页 | 列表页 | 5.1 | 增强型/全新 | 中 | 字段N+搜索N+按钮N |
   | 2 | 新增XX弹窗 | 弹窗 | 5.3.1 | 全新 | 低 | 表单N个字段 |
   | 3 | 编辑XX弹窗 | 弹窗 | 5.3.2 | 全新 | 低 | 表单N个字段 |
   | 4 | XX详情页 | 详情页 | 5.4 | 增强型/全新 | 中 | 字段N个 |
   ```

4. **确定设计顺序**（推荐）：
   - 先做列表页（主页面，确定整体布局和侧边栏）
   - 再做弹窗（从列表页的按钮触发）
   - 最后做详情页（从列表页的名称链接跳转）

5. **初始化 .pen 文件**：
   ```bash
   cp "${ZCODE_DESIGN_LIB}/dayu_platform.lib.pen" "需求/active/{module}/{slug}/07-prototype/prototype.pen"
   ```
   - 在 VS Code 中打开 .pen 文件，等待 Pencil MCP 连接就绪
   - 验证连接：`mcp__pencil__get_editor_state()`
   - 读取组件库列表：`mcp__pencil__batch_get()`

6. **输出**：页面拆解计划 + 设计顺序，写入 context-snapshot 的「页面进度」表

> **等待用户确认页面清单后，Lead Agent 开始逐页调度**

## 单页模式（mode=page, page_index=N）

**目标**：只设计一个页面/弹窗，保持 context 精简。

### 输入

Lead Agent 传入：
- `page_index`：当前页面在页面进度表中的序号
- `page_name`：页面名称
- `page_type`：列表页 / 弹窗 / 详情页
- `prd_section`：PRD 中对应章节的内容（不是整个 PRD）
- `design_strategy`：来自 design-research 的设计策略摘要
- `completed_pages`：已完成页面的摘要（用于保持风格一致）

### 执行步骤

1. **确认 Pencil MCP 已连接**（规划模式已初始化）
   验证连接：`mcp__pencil__get_editor_state()`
2. **识别页面类型**，选择对应模版：
   | 页面类型 | 大禹模版 |
   |----------|----------|
   | 列表页 | MtsyV（暗色侧边栏） |
   | 表单页 | VEdnN（基础表单） |
   | 弹窗 | 大禹弹窗模版 |
   | 详情页 | MtsyV（暗色侧边栏） |

3. **从 PRD 章节提取内容**（只读传入的 `prd_section`，不读整个 PRD）：
   - 列表字段 → 表格列定义
   - 搜索条件 → 搜索表单
   - 表单字段 → 表单控件
   - 按钮操作 → 按钮组件

4. **规划当前页面布局**：
   - 映射大禹组件
   - 计算尺寸和间距
   - 如果是第一个页面（列表页）：规划导航内容（侧边栏菜单、面包屑、页面标题）
   - 如果是后续页面：复用第一个页面的导航结构

5. **知识库 + 浏览器自动化交叉验证**（增强型页面⚠️ 强制，新建页面可参考同类页面）：

   > 设计原型前必须先搞清楚现有页面实际长什么样，不能只凭 PRD 描述画原型。

   **5a. 读取知识库中对应页面文档**：
   - 读取 `大禹平台产品知识库/` 中当前页面的详细文档
   - 记录知识库描述的字段、筛选条件、操作按钮、布局结构

   **5b. 浏览器自动化访问实际页面**：
   - 使用 `mcp__playwright__browser_navigate()` 访问当前页面对应的实际平台页面
   - 实际浏览页面，理解现有布局：哪些区域、什么字段、什么交互
   - 点击操作按钮，观察弹窗/表单的实际结构
   - 如果是增强型页面（在现有页面上改造），重点观察要改造的区域

   **5c. 交叉对比，确定设计基准**：
   - 知识库和实际页面一致 → 以此为基准设计
   - 有差异 → 以实际平台为准
   - 增强型页面 → 原型必须先还原现有页面结构，再叠加 PRD 中的新增功能
   - 新建页面 → 参考同模块已有页面的布局风格，保持一致性

6. **生成当前页面**：
   使用 `mcp__pencil__batch_design()` 创建，参考已完成页面保持风格一致

7. **截图验证**：
   - `mcp__pencil__get_screenshot()` 截取当前页面
   - 检查布局、字段、组件是否与 PRD 章节一致
   - 如果是列表页，用 `mcp__pencil__snapshot_layout()` 验证表格列宽

8. **输出**：返回当前页面摘要（名称、组件数、验证状态）

> **Lead Agent 收到结果后更新 context-snapshot 页面进度表，向用户展示截图确认**

## 完整模式（手动激活，无 mode 参数）

> 兼容旧流程：手动用 `#原型设计` 激活时，按原有流程一次性完成所有页面。

### Phase 1: 初始化

1. 读取 PRD 文档（06-prd.md）
2. 复制组件库到项目目录：
   ```bash
   cp "${ZCODE_DESIGN_LIB}/dayu_platform.lib.pen" "需求/active/{module}/{slug}/07-prototype/prototype.pen"
   ```
3. 在 VS Code 中打开 .pen 文件，等待 Pencil MCP 连接就绪
4. 使用 `mcp__pencil__get_editor_state()` 验证连接
5. 使用 `mcp__pencil__batch_get()` 读取可用组件列表
6. 用 Playwright 访问现有页面截图（增强型页面必须执行）

### Phase 2: PRD 转换

识别页面类型并提取内容：

| PRD 章节 | 页面类型 | 大禹模版 |
|----------|----------|----------|
| 5.1 列表页 | 列表页面 | MtsyV（暗色侧边栏） |
| 5.3 表单 | 表单页面 | VEdnN（基础表单） |
| 5.3 弹窗 | 弹窗 | 大禹弹窗模版 |

提取：列表字段→表格列、搜索条件→搜索表单、表单字段→表单控件

### Phase 3: 规划布局

1. 规划每个页面的布局模式
2. 映射大禹组件
3. 计算尺寸和间距
4. 规划导航内容（⚠️ 强制）：侧边栏菜单、面包屑、页面标题、菜单高亮

### Phase 4: 生成原型

> **⚠️ 模板适配强制规则**：复制布局模板后，必须先清理再更新：
> 1. `mcp__pencil__batch_get(resolveInstances:true)` 读取页面直接子节点，确认是否有两个 sidebar 节点
> 2. **双层侧边栏问题**：MtsyV 模板实例有两层重叠的 sidebar（`5wpdM` 和 `WJjcr`），上层 `WJjcr` 遮挡底层 `5wpdM`。必须修改上层 `WJjcr` 的文本节点才能生效
> 3. 逐项更新上层侧边栏菜单文本（通过 `{pageId}/mK8Cg`、`{pageId}/B6ttZ` 等节点路径）
> 4. 更新顶部 header：面包屑（`{pageId}/dNrhw`、`{pageId}/JEpMN`）、用户名（`{pageId}/j3ylQ` → "王俊逸"）
> 5. 更新按钮文本：Primary Button 默认"确定"→实际操作名、Secondary Button 默认"取消"→实际操作名
> 6. 更新 Tabs 文本：默认"概览/详情/设置"→实际 Tab 名，隐藏"标签页内容区域"（`WBmws` enabled:false）
> 7. 更新弹窗内容：标题、正文、按钮文本
> 8. 设置当前页菜单高亮：对应菜单项 fill="#40536F"，文本 fill="#FB9100"
> 9. 禁止保留任何模板默认值

使用 `mcp__pencil__batch_design()` 逐步创建：

```javascript
// 复制布局模版
page = C("MtsyV", document, {name:"页面名称", x:0, y:0})

// 清理模板结构（⚠️ 强制）
U(page+"/5wpdM", {enabled:false})       // 隐藏不可见侧边栏
U(page+"/KAZ1d", {enabled:false})       // 隐藏多余菜单组

// 更新导航内容（⚠️ 强制）
U(page+"/mgAki/iHf8I/dNrhw", {content:"实际模块名"})

// 插入业务组件
searchBar = I(page+"/sAtdw", {type:"ref", ref:"Ho7FQ"})
table = I(page+"/sAtdw", {type:"ref", ref:"qEg7Q"})
pagination = I(page+"/sAtdw", {type:"ref", ref:"cDHCZ"})
```

### Phase 5: 验证

1. `mcp__pencil__get_screenshot()` 截取每个页面视觉检查
2. `mcp__pencil__snapshot_layout()` 验证表格列宽对齐

### Phase 6: 保存与导出

1. 确认 .pen 文件已保存在 `需求/active/{module}/{slug}/07-prototype/prototype.pen`
2. 使用 Pencil CLI 导出预览图：
   ```bash
   pencil --in "需求/active/{module}/{slug}/07-prototype/prototype.pen" --export "需求/active/{module}/{slug}/07-prototype/assets/preview.png" --export-scale 2
   ```

## HTML 原型工作流（备选）

当用户明确要求 HTML 原型时：

1. 技术栈：HTML5 + TailwindCSS CDN + JavaScript
2. 设计约束：禁止自定义 style、使用 Unsplash 图片、避免滚动条
3. 响应式：支持 768px、1024px、1440px
4. 交互：hover 效果（150-300ms）、cursor-pointer、对比度≥4.5:1

---

## ⚠️ 表格设计强制要求

- 所有表格列宽度之和必须 = 1112px
- 禁止单列宽度 > 300px（内容列除外）
- 表头和数据行列宽必须一致
- 设计完成后必须用 `snapshot_layout()` 验证
- 详见 `${CLAUDE_PLUGIN_ROOT}/skills/pencil/references/dayu-design-system.md` 第5.4节

## 验证检查清单

### 组件库约束
- [ ] 必须使用大禹组件库
- [ ] 禁止手写组件（分页器、按钮、表格等）

### 内容修订（必须逐项检查）
- [ ] 侧边栏菜单项已修改为实际功能名称
- [ ] 面包屑已修改为实际页面路径
- [ ] 页面标题已修改为实际功能名称
- [ ] 表格列名与 PRD 一致
- [ ] 表格数据使用真实示例数据

### 布局检查
- [ ] 组件不超出展示范围
- [ ] 无文字/组件重叠
- [ ] 搜索框字段名和值在同一行
- [ ] 表格列宽均衡分配
- [ ] 列表页有分页器

## Context Snapshot 协作

### 启动时读取
读取 `需求/active/{module}/{slug}/05-context-snapshot.md` 中的以下区块：
- 「PRD编写摘要」— 了解列表页/表单数量、关联性改动，确定原型页面范围

### 完成时返回数据（由 Lead Agent 写入 snapshot）
返回以下结构化数据：
- 更新「原型设计摘要」区块：
  - 原型格式：.pen / .html
  - 页面数量
  - 组件库：dayu / antd / 自定义
  - 页面清单：列出所有页面名称
  - 弹窗/抽屉数量
- 更新「阶段流转记录」：将「4-原型设计」标记为 completed，记录完成时间
- 更新「元信息」中的「当前阶段」为下一阶段
