# 用户视角解析器 (Agent 0)

## 定位

预处理组件。在 PRD 生成或测试用例设计之前，以每类用户的真实视角提炼业务目标和价值诉求，避免陷入"功能表面"。

核心价值：从用户目标出发，不是从功能列表出发。

## 输入/输出

**输入**：
- 需求材料（必填）：proposal 文件路径 或 原始需求描述文本
- PRD 文件路径（可选）：已有 PRD 时提供，增强分析深度
- AC 文件路径（可选）
- UI 原型路径（可选）
- 输出目录（可选）：默认 `$WORK_DIR/.cache/user-perspectives/`

**输出**：
- `{outputDir}/{role-name}.md` — 每类用户独立文档
- `{outputDir}/_summary.md` — 汇总信息

## 执行流程

### Step 0: 初始化

1. 解析路径（`WORK_DIR`、需求目录、输出目录）
2. 创建输出目录（如不存在）。默认：`$WORK_DIR/.cache/user-perspectives/`
3. 检查已有的用户视角文档：
   - 存在且需求材料修改时间早于用户视角文档 → 展示复用选项
   - 存在但需求材料修改时间晚于用户视角文档 → 提示重新分析
   - 不存在 → 继续

### Step 1: 用户角色识别

从所有可用输入材料中识别用户类型/角色。

**识别来源**（按优先级）：
1. 需求材料（proposal / 原始需求）中的直接角色声明
2. PRD 中的角色描述（如有）
3. 权限差异（不同角色看到不同页面/操作）
4. 业务流程中的参与者（申请人、审批人、执行人）

**识别维度**：
- 直接角色声明（"管理员"、"审批人"、"普通用户"等）
- 权限差异（不同角色看到不同页面/操作）
- 业务流程中的参与者（申请人、审批人、执行人）

**输出**：用户角色列表，包含角色名 + 一句话定义。

### Step 2: 角色确认面板

展示识别到的角色列表：

```
📋 识别到 {N} 类用户角色：

  1. {角色名} — {一句话定义}
  2. {角色名} — {一句话定义}
  ...

请确认：
1. 确认无误，开始分析
2. 添加角色：{角色名}
3. 移除角色：{编号}
4. 合并角色：{编号1} + {编号2}
```

### Step 3: 并行角色分析

为每类用户独立分析（可并行执行，最多 4 个并行）。

**分析模板**（`skills/user-perspective-analyzer/prompts/perspective-analyst.md`）：
模板变量：
   - `{roleName}` → 角色名
   - `{requirementMaterial}` → 需求材料内容（proposal 摘要或原始需求文本）
   - `{reqName}` → 需求/系统名称（从需求材料标题或目录名提取）
   - `{prdPaths}` → PRD 文件路径（如存在，否则为空）
   - `{acFilePath}` → AC 文件路径（如存在）
   - `{uiPrototypePaths}` → UI 原型路径（如存在）
   - `{outputPath}` → `{outputDir}/{role-name-slug}.md`
   - `{reqNo}` → 需求编号（用于 _summary.md）

**产出验证**（每个角色分析完成后）：
- 检查输出文件存在且 size > 0.5KB
- 检查包含必要的 markdown 段落标题
- 失败时记录到 `_summary.md`，不阻塞其他角色

### Step 4: 汇总输出

生成 `_summary.md`：

```markdown
# 用户视角分析汇总

## 分析信息
- 需求编号: {reqNo}
- 分析时间: {timestamp}
- 需求材料: {requirementMaterialPaths}
- PRD 文件: {prdPaths}（如有）
- 角色数量: {N}

## 角色清单
| # | 角色 | 核心目标 | 文档路径 |
|---|------|---------|---------|

## 关键发现
- {跨角色共性诉求}
- {角色间冲突点}
- {隐性需求汇总}

## 给下游的输入
- PRD 生成: 核心诉求和隐性需求应纳入 PRD 功能说明
- test-case-design: 用户视角文档路径列表（方法论文档已内嵌在 case-designer 中）
```

## 渐进式保护

- 需求材料中无法识别用户角色 → 跳过整个分析，记录到 `_summary.md`（`status: skipped`）
- 某角色分析产出为空 → 跳过该角色，不影响其他角色
- 用户视角文档仅作为可选参考，不作为硬性门禁输入
- 方法论文件不存在时，下游自动回退到现有 AC 驱动模式

## 约束

- 禁止读取代码文件（只读 PRD/AC/UI 原型/需求材料）
- 禁止合并分析（每类用户必须独立分析，避免上下文污染）
- 禁止修改 PRD/AC/UI 原型/需求材料文件
- 每类用户一个独立文档，禁止合并到单文件
