# 任务管理、需求管理、记忆与过程记录

## 任务管理规则

当用户要求创建或执行任务时，自动执行以下规则。

### 任务生命周期

```
创建 → 执行 → 评审 → 完成 → 归档
```

### 任务创建流程

1. 在 `工作管理/任务/` 下创建任务文件：`YYYY-MM-DD_任务名称.md`
2. 任务文件包含：任务信息表（创建日期/状态/负责人/目录）、背景、目标、范围、输入物、执行情况、输出物、评审记录
3. 状态标记：🚀进行中 / ✅已完成 / ⏸️已暂停 / ❌已取消

### 任务验收标准

- 任务目录结构符合规范
- PRD文档包含全部必填模块
- UI原型命名符合规范
- 任务记录完整

## 需求管理规则

需求生命周期管理，自动引导到正确位置：

| 阶段 | 目录 | 说明 |
|------|------|------|
| 问题收集 | `工作管理/需求池/00_问题池/` | 小问题、Bug反馈 |
| 想法沉淀 | `工作管理/需求池/01_想法池/` | 产品改进想法 |
| 立项登记 | `工作管理/需求池/02_PRD编写/` | 已立项，创建轻量级登记文件 |
| PRD编写 | `需求/active/[项目名称]/` | PRD、AC、功能树、菜单树均在根目录，过程文件在 .cache/ |
| 运营宣发 | `需求/[阶段]/[项目名称]/运营宣发/` | 功能上线宣发内容 |
| 完成存档 | `工作管理/需求池/03_PRD存档/` | 已完成的PRD归档 |

> `02_PRD编写/` 仅做立项登记（记录项目编号和产品项目路径），实际PRD文件和UI原型存放在 `需求/active/` 下。

## 记忆积累规则

协作过程中自动积累经验，记忆文件存放在 `工作管理/记忆/`，纳入Git版本管理：

| 触发场景 | 记忆类型 | 写入文件 |
|----------|----------|----------|
| 用户纠正了Claude的做法 | feedback | `feedback_*.md` |
| 做了一个重要项目决策 | project | `project_*.md` |
| 发现新的团队工作模式 | user | `user_*.md` |
| 找到新的外部资源 | reference | `reference_*.md` |
| 用户说"记住这个" | 按内容判断 | 对应类型文件 |

记忆升级路径：反复验证的经验 → 升级写入 CLAUDE.md 或对应规范文档。

## 过程记录规则

执行任务过程中自动记录发现的异常、知识库缺失、规范不足等问题。

### 触发条件

发现以下任一情况时自动记录：
- 知识库内容缺失或过时
- 规范体系存在漏洞
- 流程设计可优化
- 工具或环境缺陷

### 存储位置

项目目录下 `过程记录/` 子目录，文件名 `YYYY-MM-DD_分类关键词-简述.md`。

### 问题记录模板

```markdown
### [序号] 问题标题

- **发现场景**：在做什么任务时发现
- **问题描述**：具体什么内容不正确/缺失/不合理
- **影响范围**：对当前任务的影响
- **建议改进**：后续应如何优化
- **分类标签**：`知识库缺失` / `知识库过时` / `规范缺失` / `规范优化` / `流程优化` / `工具缺陷`
```

### 不记录的情况

- 用户操作失误导致的临时问题
- 已知且已接受的技术限制
- 与当前任务无关的发现
