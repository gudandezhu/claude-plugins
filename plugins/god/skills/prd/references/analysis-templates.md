## 模板3：需求挑战记录

```markdown
## 模块1.2：需求挑战记录

| 挑战维度 | 原始需求描述 | 挑战问题 | 用户回应 | 调整结论 |
|---------|------------|---------|---------|---------|
| 问题vs方案 | | | | 维持/调整 |
| 范围合理性 | | | | 维持/调整 |
| 用户真实诉求 | | | | 维持/调整 |
```

**挑战维度说明**：

- **问题 vs 方案**：用户描述的是真正的问题，还是已经预设了解决方案？
- **范围合理性**：需求范围是否过大（应该拆期）或过小（遗漏关键场景）？
- **用户真实诉求**：用户说的和用户真正需要的是否一致？

## 模板4：用户角色与场景

```markdown
## 模块1.3：用户角色与场景

### 目标用户角色
- **主要角色**：_________
  - 角色描述：_________
  - 使用频率：_________
  - 技术水平：_________

- **次要角色**：_________
  - 角色描述：_________
  - 使用频率：_________

### 主要使用场景
- **场景1**：_________
  - 触发条件：_________
  - 用户目标：_________
  - 当前痛点：_________

- **场景2**：_________
  - 触发条件：_________
  - 用户目标：_________

### 用户旅程和痛点分析
- **现有流程**：_________
- **关键痛点**：_________
- **期望改进**：_________
```

**场景挖掘方法（5W1H）**：
- Who（谁）：哪些角色会使用？
- What（什么）：要完成什么任务？
- When（何时）：在什么场景下使用？
- Where（何地）：在什么环境下使用？
- Why（为什么）：为什么要这样做？
- How（如何）：希望如何实现？
