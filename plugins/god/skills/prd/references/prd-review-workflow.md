# 需求文档自审工作流程

## 自审触发规则

当完成需求文档（PRD）编写后，AI 助手必须自动引导用户进行需求文档自审流程。

### 触发条件
- 完成 PRD 文档的创建或重大修改
- 用户明确表示需求文档已完成
- 准备提交审核前

---

## 分级自审机制

根据**需求规模**选择合适的自审级别：

### 轻量级自审（5项检查）
**适用场景**：小型需求（1-3人天），标准CRUD功能

**核心检查项**（5项）：
1. ✅ 需求目标明确
2. ✅ 功能描述完整
3. ✅ 字段定义清晰
4. ✅ 异常处理考虑
5. ✅ 权限控制明确

**预计时间**：5-10分钟

### 标准自审（12项检查）
**适用场景**：中型需求（4-10人天），有一定复杂度的功能

**核心检查项**（12项）：
1. ✅ 需求目标明确
2. ✅ 功能描述完整
3. ✅ 字段定义清晰
4. ✅ 异常处理考虑
5. ✅ 权限控制明确
6. ✅ 交互流程合理
7. ✅ 业务实体页面完整性（每个实体的标准页面集齐全：列表/详情/新增/编辑/删除）
8. ✅ 导航闭环完整性（菜单→页面→返回路径无断裂，无孤立页面和死胡同）
9. ✅ 接口定义完整
10. ✅ 性能指标明确
11. ✅ 兼容性说明
12. ✅ 文档质量良好

**预计时间**：10-15分钟

### 完整自审（18项检查）
**适用场景**：大型需求（10+人天），复杂业务流程，多系统对接

**全部检查项**（18项）：
1. ✅ 需求目标与用户价值
2. ✅ 概念与术语一致性
3. ✅ 功能完整性与场景覆盖
4. ✅ 用户操作复杂度
5. ✅ 界面组件规范性
6. ✅ 数据字段完整性
7. ✅ 业务规则清晰度
8. ✅ 系统集成与接口依赖
9. ✅ 权限与安全控制
10. ✅ 性能与非功能性需求
11. ✅ 错误处理与用户反馈
12. ✅ 可扩展性与复用性
13. ✅ 对现有系统的影响
14. ✅ 验收标准明确性
15. ✅ 文档质量与准确性
16. ✅ 业务流程→原型映射（流程图每个步骤在原型中有对应页面/交互）
17. ✅ 状态机交互完整性（每个状态转换有对应的操作入口和目标状态展示）
18. ✅ 关联系统影响评估（PRD 关联改动章节的每项改动已评估影响范围）

**预计时间**：20-25分钟

### 级别选择原则

| 需求规模 | 需求类型 | 推荐级别 | 必选检查项 |
|---------|---------|---------|-----------|
| 小型（1-3人天） | 标准CRUD、简单查询导出 | 轻量级 | 5项核心 |
| 中型（4-10人天） | 有一定复杂度的功能 | 标准级 | 10项核心 |
| 大型（10+人天） | 复杂流程、多系统对接 | 完整级 | 15项全面 |

**特殊情况**：
- 涉及安全敏感数据 → 使用完整级（至少包含安全检查项）
- 核心业务功能 → 使用标准级或完整级
- 优化类需求 → 使用轻量级

## 自审流程执行步骤

### 第一步：自动提醒自审并选择级别

当需求文档完成后，AI 助手应主动提醒：

```
需求文档已完成。根据团队规范，现在需要进行需求文档自审。

根据你的需求规模，我建议选择以下自审级别：

□ 轻量级自审（5项检查，5-10分钟）
  适用于：小型需求（1-3人天），标准CRUD功能

□ 标准自审（10项检查，10-15分钟）
  适用于：中型需求（4-10人天），有一定复杂度的功能

□ 完整自审（15项检查，15-20分钟）
  适用于：大型需求（10+人天），复杂业务流程，多系统对接

当前需求规模：_________人天
推荐级别：_________

请选择自审级别，或使用推荐级别。
```

**AI助手判断逻辑**：
- 根据阶段1记录的"需求规模"自动推荐级别
- 小型（1-3人天）→ 推荐轻量级
- 中型（4-10人天）→ 推荐标准级
- 大型（10+人天）→ 推荐完整级
- 用户确认级别后，进入第二步

**级别确认示例对话**：
```
用户：使用标准级
AI：好的，将使用标准自审（10项检查），预计耗时10-15分钟。
准备开始第一项检查...
```

---

### 第二步：逐项引导检查（根据选定级别）

如果用户同意开始自审，AI 助手应：

1. **逐项展示检查问题**：按照自审清单的顺序，逐个展示检查项
2. **提供检查要点**：明确说明每个检查项的关键要点
3. **针对性分析**：基于当前 PRD 文档内容，指出可能存在的问题
4. **等待用户确认**：让用户确认该项是否通过

示例对话：
```
【检查项 1/15】需求目标与用户价值

问题：需求的目标和背景是否明确？目标用户是否定义清楚？用户是否可以通过该需求完成他的目标？

检查要点：
- 业务目标清晰
- 用户角色明确
- 使用场景完整
- 能够解决用户实际问题

基于当前文档分析：
[AI 助手分析当前 PRD 文档在这一项的完成情况]

该项是否通过？(通过/待改进/不适用)
```

### 第三步：问题汇总与改进
完成所有检查项后，AI 助手应：

1. **统计检查结果**：
   - 通过项数量
   - 待改进项数量
   - 不适用项数量

2. **汇总主要问题**：列出所有待改进的问题

3. **判断自审结论**：
   - 如果存在高优先级问题（必须解决），判定为"需要改进"
   - 如果仅存在中低优先级问题，由用户决定是否改进

4. **提供改进建议**：针对每个待改进项，提供具体的改进建议

### 第四步：持续优化循环
如果自审不通过：

1. **明确改进项**：列出需要改进的具体内容
2. **协助优化**：根据用户选择，协助修改 PRD 文档
3. **重新自审**：完成修改后，重新进行相关检查项的自审
4. **循环直至通过**：重复优化和自审过程，直到所有高优先级问题解决

示例对话（标准级10项检查）：
```
自审结果汇总（标准级自审）：
- 总检查项：10 项
- 通过项：8 项
- 待改进项：2 项
- 不适用项：0 项

待改进问题：
1. 【高优先级】数据字段定义不完整，缺少字段长度和校验规则
2. 【中优先级】异常场景处理不完整，未考虑接口调用失败的情况

自审结论：需要改进后再提交审核

建议优化顺序：
1. 首先完善数据字段定义（高优先级，必须解决）
2. 补充异常场景处理（中优先级，建议解决）
3. 优化错误提示信息（低优先级，可选）

是否现在开始优化文档？我可以协助你逐项改进。
```

## 自审标准参考

### 高优先级问题（必须解决）
- 需求目标不明确或用户无法完成目标
- 核心功能缺失或业务流程不完整
- 数据字段定义不完整或校验规则缺失
- 权限控制方案缺失或存在安全风险
- 对现有系统影响未评估
- 业务实体缺少标准页面（如有列表页但无详情页）
- 导航路径存在死胡同或孤立页面

### 中优先级问题（建议解决）
- 用户操作存在重复或复杂
- 使用非标准组件但未充分说明必要性
- 异常场景处理不完整
- 性能指标未明确定义
- 文档存在歧义或前后矛盾

### 低优先级问题（可优化）
- 可扩展性设计不足
- 错误提示不够友好
- 文档格式不够规范
- 缺少部分图表说明

## AI 助手行为规范

### 必须执行的行为
1. **主动提醒**：完成 PRD 后必须主动提醒进行自审
2. **逐项检查**：按照清单顺序逐项引导检查
3. **针对性分析**：基于实际文档内容进行分析，不能泛泛而谈
4. **明确结论**：给出清晰的自审结论（通过/需要改进）
5. **持续跟进**：如果不通过，持续协助优化直到通过

### 禁止的行为
1. **跳过自审**：不能在完成 PRD 后直接结束，必须引导自审
2. **走过场**：不能简单地说"文档很好，通过自审"，必须逐项检查
3. **模糊结论**：不能给出模棱两可的结论，必须明确通过或不通过
4. **放弃优化**：如果不通过，不能让用户自行修改，必须提供协助

## 特殊情况处理

### 用户拒绝自审
如果用户明确表示不需要自审：
```
理解你的选择。但根据团队规范，建议在提交审核前完成自审，这可以：
- 提高审核通过率
- 减少返工时间
- 确保文档质量

如果你确定跳过自审，请确认：我确认跳过自审流程
```

### 用户要求快速自审
如果用户时间紧张，可以提供轻量级自审模式（对应快速自审）：
```
理解你的时间紧迫。我可以提供轻量级自审模式（5项核心检查），预计耗时5-10分钟：
1. 需求目标明确
2. 功能描述完整
3. 字段定义清晰
4. 异常处理考虑
5. 权限控制明确

是否使用轻量级自审模式？
```

**注意**：快速自审模式等同于轻量级自审，适用于小型需求或时间紧迫的情况。

### 部分改进后的再次自审
如果用户只改进了部分问题：
```
已完成部分改进。现在重新检查已修改的项：
[列出已修改的检查项]

其他待改进项：
[列出未修改的检查项]

是否继续改进其他项？
```

## 自审记录保存

完成自审后，AI 助手应建议：
```
自审已完成。建议保存自审记录：
1. 将自审结果填写到《需求文档自审清单.md》
2. 作为 PRD 文档的附件一并提交
3. 便于审核人员了解文档质量

是否需要我帮你生成自审记录文档？
```

## 工作流程图

```
PRD 文档完成
    ↓
AI 主动提醒自审
    ↓
用户同意 → 开始逐项检查（15项）
    ↓
每项检查：展示问题 → 分析文档 → 用户确认
    ↓
汇总检查结果
    ↓
判断优先级 → 给出自审结论
    ↓
通过？
    ├─ 是 → 建议保存自审记录 → 结束
    └─ 否 → 列出待改进项 → 协助优化 → 重新自审（循环）
```

## 总结

通过这个自动化的自审工作流程，确保：
1. 每个 PRD 文档都经过系统化的质量检查
2. 问题在提交审核前被发现和解决
3. 文档质量持续提升
4. 减少审核返工，提高工作效率
