# PRD编写 - 准备阶段

> 本文件由 `/zcode:prd` 命令 Phase 3.5 调度，也支持 Lead PRD Agent 按需加载。

## 角色

PRD编写准备阶段执行者。确认输入信息完整，核对平台知识库，确定编写策略。

## 执行步骤

### 1. 创建项目输出目录（⚠️ 强制）

- 所有PRD产出文件必须保存在 `$PROJECT_DIR` 目录下
- 图表等资源文件保存在 `$PROJECT_DIR/assets/` 子目录下
- 禁止将PRD文件保存到 `.claude/wiki/`、`.claude/` 或其他非 `prd/` 的目录

### 2. 确认前置条件

- 检查是否已完成需求分析（01-requirements-analysis.md）
- 检查是否已完成功能范围规划（02-feature-scope.mm，FreeMind 格式，可用 XMind 打开）
- 确认需求的规模和复杂度

### 3. 核对平台知识库（⚠️ 类型驱动，按需执行）

> 仅当类型文件声明了知识库规则时执行此步骤。如 `$PRD_TYPE` 的类型文件包含 Phase 1 增强规则（如 dayu 类型的"平台能力审计"），则必须执行。
- 读取类型文件指定的知识库中与本需求涉及的每个页面对应的子页面文档
- 逐字段记录现有页面的完整结构（筛选条件、列表字段、操作按钮、统计卡片、数据规模）
- 增强型页面必须先完整列出现有字段，再标注新增字段，每个字段标注"现有"或"新增"
- 参考现有页面的字段命名、筛选条件设计、操作按钮布局，确保与平台现有风格一致
- 在 PRD 的"关联性需求改动"章节中，引用知识库中受影响的现有页面
- 禁止凭记忆或假设描述现有页面结构，必须以知识库文档为准

**知识库信息不足时的兜底**：
- 如果知识库中没有对应页面的文档，使用 Playwright 访问实际页面获取信息
- 使用 `mcp__playwright__browser_navigate()` 访问页面路由，`mcp__playwright__browser_take_screenshot()` 截取页面截图
- 从截图中提取筛选条件、列表字段、操作按钮等结构信息
- Playwright 是知识库的**兜底补充**，不是常规验证手段——仅在知识库无记录时使用

### 4. 选择表格填写模式

```markdown
根据功能复杂度，确定表格填写模式：

□ **简洁表格**：3列表格（字段名称 | 类型 | 说明）
  适用：简单字段，标准CRUD功能

□ **详细表格**：5-7列表格（序号 | 字段名称 | 取值示例 | 取值说明 | 字符长度 | 必填 | 规则说明）
  适用：复杂字段，特殊业务逻辑

当前需求建议使用：_________模式
```

### 5. 确认多系统对接

- 是否涉及多个系统交互？
- 是否需要数据流图？

## 输出

完成后向 Lead Agent 返回：
- 前置条件检查结果
- 知识库核对摘要（涉及的现有页面及字段数量）
- 表格模式选择
- 多系统对接情况

**GATE: 禁止进入建模阶段。必须等待用户确认后才能继续。如果用户未回复，重复询问一次后停止。**
