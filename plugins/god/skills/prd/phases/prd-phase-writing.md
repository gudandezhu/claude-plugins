# PRD编写 - 编写阶段

> 本文件由 `/zcode:prd` 命令 Phase 4 或 Lead PRD Agent 按需加载。

## 角色

PRD编写阶段执行者。基于前序阶段的分析成果，根据 `$PROJECT_DIR/.cache/module-config.md` 中激活的模块列表，按批次写入PRD文档。

## 启动前提

1. 读取 `$PROJECT_DIR/.cache/module-config.md`，获取：
   - 场景类型（A/B/C/D，可多选）
   - 激活的模块列表
   - 批次划分
2. 加载写作规范+模板：读取 `${CLAUDE_PLUGIN_ROOT}/skills/prd/references/prd-writing-guide.md`
3. 加载格式：读取 `${CLAUDE_PLUGIN_ROOT}/skills/prd/references/prd-format-templates.md`

## 执行框架

### 批次调度逻辑

根据激活模块按以下5批次顺序执行。如果某批次的所有模块均未激活，跳过该批次。

| 批次 | 模块 | 目的 | GATE |
|------|------|------|------|
| **1.对齐** | M01 + M02 + M03a + M05(如激活) | 确立 Why + Who + 验收维度 + 边界 | ✅ 必须等用户确认 |
| **2.建模** | M19(如激活) + M08(如激活) + M06(如激活) | 业务域 + 数据模型 + 功能范围 | ✅ 必须等用户确认 |
| **3.细节** | M07(如激活) + M09 + M10(如激活) | 流程 + 功能细节 + 关联���响 | ✅ 必须等用户确认 |
| **4.质量** | M11 + M12(如激活) + M13(如激活) | 异常 + 权限 + 非功能 | ✅ 必须等用户确认 |
| **5.收尾** | M03b + M16(如激活) + M14/M15/M17(如激活) | 详细验收 + 风险 + 编码/版本/运营 | ✅ 必须等用户确认 |

### 每批次内模块执行顺序

批次内模块按固定顺序连续生成（无 GATE），相邻轻量模块可合并为一次写入：

- 批次1：M01(Write创建文件) → M02(Edit append) → M03a(Edit append) → M05(Edit append,如激活)
- 批次2：M19 → M08 → M06（均如激活，按此顺序）
- 批次3：M07 → M09 → M10（均如激活）
- 批次4：M11 → M12 → M13（M11必选，M12/M13如激活）
- 批次5：M03b → M16 → M14 → M15 → M17（M03b必选，其余如激活）

### GATE 规则

- 每批次完成后必须等待用户确认，确认后才能继续下一批次
- 用户说"继续"或"没问题"视为确认通过
- 用户提出修改 → 修改后重新展示该批次 → 再次确认
- 如果用户未回复，重复询问一次后停止

## 文件写入规则（⚠️ 强制）

为避免单次输出过长导致写入失败，必须遵循以下策略：

1. **批次1第一个模块**：使用 Write 工具创建 `$PRD_OUTPUT`，写入 M01 + M02 + M03a
2. **后续所有内容**：使用 Edit 工具，以 append 方式追加到文件末尾
3. **M09 功能详细说明按子章节分批写入**
   - 每个页面的列表描述 → 单独一次 Edit
   - 每个页面的按钮+表单描述 → 单独一次 Edit
   - 关联性需求改动 → 单独一次 Edit
4. **单次写入上限**：每次 Edit/Write 内容不超过 200 行
5. **超限处理**：如果某个子章节预估超过 200 行，按页面或按表格进一步拆分

**Edit append 方法**：`old_string` 取文件当前最后一段内容（如末尾的 `---` 或最后一个章节的最后几行），`new_string` 为该内容 + 新追加的内容。

## 三条元原则

1. **严格遵循批次+GATE**：按 5 批次顺序执行，每批次完成后等用户确认。禁止一次性完成所有批次，禁止跳过 GATE
2. **内容完整且用业务语言**：表格必须完整（每个字段都有说明），关联���分析不能遗漏，使用业务语言描述（禁止开发术语，与 SKILL.md 硬性规则对齐）
3. **只生成激活模块**：只处理 module-config.md 中标记为激活的模块，禁止生成未激活模块的内容

## Context Snapshot 协作

### 启动时读取
读取 `$PROJECT_DIR/05-context-snapshot.md` 中的以下区块：
- 「需求摘要」— 了解需求名称、核心目标、用户角色、关键约束

### 完成时返回数据（由 Lead Agent 写入 snapshot）
返回以下结构化数据：
- 更新「PRD编写摘要」区块：
  - 场景类型：A/B/C/D
  - 已完成模块：列出完成的模块ID和名称

  - 多系统对接：是/否及涉及系统
  - 关联性改动：受影响的现有页面/模块列表
  - 待确认事项：编写阶段遗留的开放问题
- 更新「阶段流转记录」：将「3-PRD编写」标记为 completed，记录完成时间
- 更新「元信息」中的「当前阶段」为下一阶段
