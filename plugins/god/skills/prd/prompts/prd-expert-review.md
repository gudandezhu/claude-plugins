# PRD 多维度专家评审模块

## 设计理念

PRD 的核心价值是**说清业务问题**。评审的重点不是格式扣分，而是发现真正的业务风险和逻辑漏洞。

采用 **4 个并行专家 SubAgent**，每个专家专注 1 个维度深度挖掘，主 agent 综合评分。

## 变量

调用时替换以下变量：
- `{prdPath}` → 实际 PRD 文件路径
- `{perspectiveSummaryPath}` → 用户视角分析汇总路径
- `{perspectiveDir}` → 用户视角分析详情目录
- `{proposalPath}` → proposal 路径
- `{activeModules}` → 本次激活的模块列表（如 "M01,M02,M03a,M05,M06,M07,M09,M11,M03b,M16"）
- `{scenarioType}` → 场景类型（如 "A"、"B+C"）

**动态检查规则**：评审专家仅检查 `{activeModules}` 中已激活的模块。未激活模块的检查项自动跳过，不影响评分。

## Phase 1: 并行专家评审

使用 Agent 工具并行启动 4 个 general-purpose SubAgent，每个传入对应的专家 prompt。

---

### 专家 1: 业务价值专家（30%）

**评审角度：** PRD 是否清晰表达了业务问题、现状差距、改动范围，业务逻辑是否准确。

**Prompt 模板：**

```
你是资深产品总监。从业务视角深度评审 PRD 文档。

先依次读取：
1. PRD：{prdPath}
2. 用户视角汇总：{perspectiveSummaryPath}
3. Proposal：{proposalPath}

## 评审任务

### 1. 现状-目标-差距分析质量
检查 M02（需求背景与目标）：
- 现状描述是否具体（"当前采购单只能整单提交，无法分批" 而非 "系统不支持分批提交"）
- 目标是否可量化（有具体数值，不是"提升效率"）
- 差距是否逐条对应目标
- 改动范围是否标注了新增/修改/复用

### 2. 业务逻辑准确性
- 每个功能点的业务规则描述是否准确（触发条件、数据变化、结果）
- 是否有功能点只描述了"是什么"没描述"业务规则是什么"
- 数据流转路径是否清晰

### 3. 改动范围合理性
- 改动范围是否完整（有无遗漏的关联模块）
- 改动类型标注（新增/修改/复用）是否合理
- 是否有不必要的改动（过度设计）

### 4. 业务价值闭环
- 每个功能点是否可追溯到业务目标
- 是否有功能点与业务目标无关
- 用户视角分析中的核心诉求是否在 PRD 中有体现

## 输出格式

```
## 评分：X/30

## 业务差距分析质量
| 检查项 | 结论 | 问题 |
|--------|------|------|

## 业务逻辑问题
| 功能点 | 问题描述 | 严重程度 |
|--------|---------|---------|

## 改动范围问题
| 问题 | 说明 | 建议 |
|------|------|------|

## P0 问题（必须修复）
1. ...

## P1 问题（建议修复）
1. ...

## P2 问题（供参考）
1. ...
```
```

### 专家 2: 流程自洽专家（25%）

**评审角度：** 业务流程是否闭环、数据流转是否一致、状态变更是否完整。

**Prompt 模板：**

```
你是资深业务架构师。评审 PRD 文档的业务流程自洽性。

先读取 PRD：{prdPath}

## 评审任务

### 1. 流程闭环
- 每个业务流程是否有明确的起点和终点
- 流程中的每个分支（含异常分支）是否都有处理方案
- 跨流程衔接是否一致（A 流程的输出是否 = B 流程的输入）

### 2. 状态流转完整性
- 是否存在孤立状态（无法到达或无法离开）
- 状态变更的条件是否明确
- 状态变更触发的动作是否完整

### 3. 数据流转一致性
- 同一字段/概念在不同模块中名称是否一致
- 数据变更描述是否前后矛盾（同一操作不能有两种不同结果）
- 约束条件在所有引用点是否保持一致

### 4. 流程与功能对应
- 流程图中的每个节点是否在功能说明中有对应
- 功能说明中的操作是否在流程图中有体现

## 输出格式

```
## 评分：X/25

## 流程闭环问题
| 流程 | 问题 | 严重程度 |
|------|------|---------|

## 状态流转问题
| 状态 | 问题 | 建议 |
|------|------|------|

## 数据一致性问题
| 字段/概念 | 位置A | 位置B | 矛盾描述 |
|-----------|-------|-------|---------|

## P0 问题（必须修复）
1. ...

## P1 问题（建议修复）
1. ...
```
```

### 专家 3: 场景覆盖专家（25%）

**评审角度：** 每类角色的场景是否被覆盖、异常是否充分、边界条件是否完整。

**Prompt 模板：**

```
你是资深 QA 测试架构师 + UX 专家。评审 PRD 文档的场景覆盖度。

先依次读取：
1. PRD：{prdPath}
2. 用户视角汇总：{perspectiveSummaryPath}
3. 用户视角详情：{perspectiveDir} 下所有 .md 文件

## 评审任务

### 1. 角色场景覆盖
- 每个角色（从用户视角分析中获取）在 PRD 中是否有对应场景
- 每个角色的关键操作流程是否在功能说明中有对应
- 是否存在"有角色无场景"或"有场景无角色"的断裂

### 2. 异常场景充分性
- 是否覆盖四维度：数据异常 + 操作异常 + 权限异常 + 环境异常
- 每条异常是否含完整四列：触发条件→系统行为→提示文案→恢复方式
- 是否有正常流程缺少对应的异常处理

### 3. 边界条件
- 空数据、极大值、精度溢出等数据边界
- 并发操作、网络异常等时序边界
- 权限切换、跨数据范围等权限边界

### 4. 用户视角隐性需求
- 用户视角分析中标记的隐性需求是否被纳入或明确标注为"后续版本"
- 每类用户的核心诉求是否在异常/验收中有体现

## 输出格式

```
## 评分：X/25

## 角色覆盖矩阵
| 角色 | 场景覆盖 | 缺失场景 |
|------|---------|---------|

## 异常场景缺陷
| 维度 | 覆盖情况 | 遗漏 |
|------|---------|------|

## 边界条件遗漏
| 类别 | 遗漏项 | 严重程度 |
|------|--------|---------|

## 隐性需求覆盖
| 隐性需求 | PRD 体现 | 缺失 |
|---------|---------|------|

## P0 问题（必须修复）
1. ...

## P1 问题（建议修复）
1. ...
```
```

### 专家 4: 可测试性专家（20%）

**评审角度：** 每条需求是否可判定、验收标准是否具体、非功能需求是否有明确指标。

**Prompt 模板：**

```
你是资深需求评审专家。逐条审查 PRD 中每个需求的可测试性。

先读取 PRD：{prdPath}

## 评审任务

### 1. 需求可判定性
逐条检查每个功能点和业务规则：
- 是否有明确的"通过/不通过"判定标准
- 是否存在模糊描述（"适当"、"合理"、"相关规范"）
- 是否存在条件性表述（"如业务允许"、"以实际配置为准"）

### 2. 验收标准质量
- 是否同时包含功能级验收和 E2E 全链路验收
- E2E 是否与流程图一一对应
- 验收标准是否用具体输入和可判定结果（禁止"输入一些数据"）

### 3. 非功能需求指标
- 性能指标是否有具体数值（如"加载≤2秒"，非"响应要快"）
- 安全要求是否有具体措施
- 兼容性是否有明确范围

### 4. 格式合规
- 是否全面表格化（禁止大段纯文本）
- 业务流程是否同时包含 Mermaid 图 + 节点说明表
- 待确认项是否已转为陈述性结论（禁止问号）

## 输出格式

```
## 评分：X/20

## 不可判定需求
| 需求位置 | 原文 | 问题 | 修改建议 |
|---------|------|------|---------|

## 验收标准缺陷
| 缺陷类型 | 位置 | 说明 |
|---------|------|------|

## 非功能指标问题
| 维度 | 问题 | 建议指标 |
|------|------|---------|

## 格式问题
| 位置 | 问题 | 修正建议 |
|------|------|---------|

## P0 问题（必须修复）
1. ...

## P1 问题（建议修复）
1. ...
```
```

## Phase 2: 综合评分

主 agent 收集 4 个专家报告后，按 4 维度综合评分：

| 维度 | 满分 | 评分来源 | 扣分规则 |
|------|------|---------|---------|
| 业务价值 | 30 | 专家 1 报告 | 现状描述模糊每处扣3分；目标不可量化每处扣3分；差距无追溯每处扣2分；功能与目标无关每处扣2分；用户诉求遗漏每处扣2分 |
| 流程自洽 | 25 | 专家 2 报告 | 流程断点每处扣3分；状态孤立每处扣3分；数据名称不一致每处扣2分；数据矛盾每处扣3分；流程与功能不对应每处扣2分 |
| 场景覆盖 | 25 | 专家 3 报告 | 角色无场景每处扣3分；异常维度缺失每维度扣3分；异常缺四列每处扣1分；边界遗漏每处扣1分；隐性需求遗漏每处扣2分 |
| 可测试性 | 20 | 专家 4 报告 | 不可判定需求每处扣3分；模糊描述每处扣2分；E2E缺失每处扣2分；非功能无指标每处扣2分；格式问题每处扣1分 |

### 评分原则

1. **以专家发现的问题为准**，不重复检查
2. **P0 问题直接影响总分**，P0 超过 3 个则自动不通过（无论总分）
3. **同一问题在多个维度被发现的，按较重维度扣分**（不重复扣）
4. 扣分不设下限（最低 0 分），不设上限（最高扣到维度满分）

### 通过标准

- **总分 ≥ 90 分**：通过
- **总分 < 90 分**：不通过
- **P0 问题 > 3 个**：不通过（无论总分）

不通过时根据专家报告修复 PRD，再次评审。最多循环 2 次。
