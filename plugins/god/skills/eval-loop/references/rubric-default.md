# 默认通用评估 Rubric

总分 100 分，**≥ 90 分通过，< 90 分不通过**。每个检查项按三级评分：通过（满分）、部分通过（50%）、不通过（0 分）。部分通过适用于：内容存在但不够完整/精确，而非完全缺失。

## 维度汇总

| 维度 | 满分 |
|------|------|
| 完整性 | 25 |
| 正确性 | 25 |
| 清晰性 | 20 |
| 一致性 | 15 |
| 可操作性 | 15 |
| **合计** | **100** |

---

## 完整性（满分 25）

检查目标内容是否覆盖了所有必要部分，无遗漏。

- [10分] 核心内容完整 — 主题所涉及的关键要素是否全部覆盖，有无明显缺失的章节、模块或功能点
- [5分] 边界与异常覆盖 — 是否覆盖了边界情况、异常场景、错误处理等非主路径内容
- [5分] 上下文自足 — 读者无需额外查阅其他资料即可理解核心内容，必要的背景信息是否已包含
- [5分] 输入输出明确 — 涉及输入输出的地方（参数、返回值、数据流）是否都有明确定义

## 正确性（满分 25）

检查内容的事实准确性、逻辑合理性和方案有效性。

- [10分] 事实准确 — 引用的数据、API、技术细节是否正确，无错误引用或过时信息
- [10分] 逻辑合理 — 推理过程是否严密，因果关系是否成立，方案是否能解决目标问题
- [5分] 方案有效 — 提出的解决方案是否切实可行，而非空泛的理论描述

## 清晰性（满分 20）

检查内容的结构和表达是否清晰易懂。

- [8分] 结构清晰 — 内容组织是否有逻辑层次（章节、列表、表格），读者能快速定位关键信息
- [7分] 语言精确 — 表述是否无歧义，术语使用是否准确，无模糊或含糊的描述
- [5分] 重点突出 — 关键信息是否通过格式（加粗、列表、标题）得到强调，不被次要信息淹没

## 一致性（满分 15）

检查内容内部及与外部标准的一致性。

- [5分] 术语一致 — 同一概念是否始终使用相同术语，无同一事物不同称呼的情况
- [5分] 内部逻辑一致 — 各部分描述是否相互印证，无自相矛盾之处
- [5分] 格式一致 — 标题层级、列表格式、命名风格是否统一

## 可操作性（满分 15）

检查内容是否可被执行或验证。

- [5分] 步骤可执行 — 涉及操作步骤的内容是否足够具体，读者可直接照做
- [5分] 验收可判定 — 验收标准或成功条件是否可被客观判定（非"看起来正常"等主观描述）
- [5分] 示例可复现 — 如包含示例（代码、命令、配置），是否可直接复制使用且能正确运行

---

## 评分校准

- 每个检查项按三级评分：通过（满分）、部分通过（50%）、不通过（0 分）
- 扣分项必须附上具体位置和改进建议
- 单个高权重检查项失分（如核心内容缺失 -10 分）往往直接导致不通过
- **≥ 90 分通过，< 90 分不通过**

## 完成前验证

在输出评审结论前，你必须自我验证：
- [ ] 我是否读取了完整的目标内容（不是只看摘要或部分章节）？
- [ ] 我是否对每个检查项都给出了基于证据的判断（不是凭印象）？
- [ ] 我标记的问题是否都附带了具体位置和改进建议？
- [ ] 我的评分是否与检查结果一致（没有漏扣或多扣）？
