# prototype-iterate 命令

## 命令说明

对已有的 Pencil 原型（.pen 文件）执行 3 轮迭代优化，逐步提升原型质量。适用于原型初稿完成后的独立优化场景，无需跑完整 /prd 流程。

## 使用方式

### 指定项目
```
/prototype-iterate {slug}
```
自动定位 `需求/active/{module}/{slug}/07-prototype/prototype.pen` 和 `需求/active/{module}/{slug}/06-prd.md`。

### 指定 .pen 文件
```
/prototype-iterate path/to/file.pen
```
手动指定 .pen 文件路径，需同时告知 PRD 文档位置。

### 从指定轮次开始
```
/prototype-iterate {slug} 从第2轮开始
```
跳过已完成的轮次，从指定轮次继续。

## 前置条件

| 条件 | 说明 |
|------|------|
| .pen 文件已存在 | 原型初稿已生成（至少有页面骨架） |
| PRD 文档已存在 | 用于字段核对和操作闭环验证 |
| Pencil MCP 已连接 | VS Code 中已打开 .pen 文件 |

## 3 轮迭代模型

### 第1轮：结构骨架验证

**关注点**：页面结构、组件布局、导航内容

**操作**：
1. 确认 Pencil MCP 已连接（VS Code 中已打开 .pen 文件）
2. 使用 `mcp__pencil__batch_get()` 读取所有页面节点树
3. 使用 `mcp__pencil__get_screenshot()` 逐页截图
3. 逐页检查：

| 检查项 | 通过标准 |
|--------|---------|
| 页面布局模式 | 侧边栏+内容区结构正确 |
| 侧边栏菜单 | 已更新为实际功能名称，无模板默认值 |
| 面包屑路径 | 与页面层级一致 |
| 主要区域 | 搜索栏/表格/分页器（或表单区域）已就位 |
| 模板残留 | 无默认内容残留 |

4. 发现问题 → 使用 `mcp__pencil__batch_design()` 修复 → 重新截图确认

### 第2轮：内容填充与精度

**关注点**：字段内容、表格精度、与 PRD 一致性

**操作**：
1. 读取 PRD 文档（06-prd.md），提取字段表格、搜索条件表格、状态定义
2. 逐页对照 PRD 检查：

| 检查项 | 通过标准 |
|--------|---------|
| 表格列宽 | 总和 = 1112px（使用 `snapshot_layout` 验证） |
| 表头字段 | 与 PRD 字段表格一一对应（无遗漏、无多余） |
| 搜索条件 | 与 PRD 搜索条件表格一致 |
| 状态徽章 | 颜色与设计规范一致 |
| 示例数据 | 合理的业务数据（非 lorem ipsum） |
| 表单字段 | 与 PRD 字段说明表格一致（表单页） |
| 操作栏 | 包含"常用功能："标签 |

3. 发现不一致 → 修复 → `snapshot_layout` 重新验证对齐

### 第3轮：打磨与一致性

**关注点**：跨页面一致性、弹窗补全、操作闭环

**操作**：
1. 截取所有页面截图，横向对比
2. 检查：

| 检查项 | 通过标准 |
|--------|---------|
| 侧边栏一致性 | 所有页面菜单结构完全一致 |
| 当前页高亮 | 每个页面对应的菜单项正确高亮 |
| 弹窗补全 | PRD 中有新增/编辑/删除操作 → 对应弹窗存在 |
| 操作闭环 | 每个操作按钮有对应的目标页面/弹窗 |
| 卡片样式 | R() 替换后保留 fill/cornerRadius/padding/stroke |
| 视觉统一 | 颜色、字体、间距全局一致 |

3. 补全缺失的弹窗和交互状态页面
4. 修复跨页面不一致问题

### 第4轮：PRD 覆盖度逐项核对

**关注点**：PRD 中定义的每个页面、每个操作、每个字段是否在原型中完整体现

**操作**：
1. 逐章节对照 PRD 功能描述（5.x 章节），检查：

| 检查项 | 通过标准 |
|--------|---------|
| 页面覆盖 | PRD 定义的每个页面/区块在原型中存在 |
| 操作覆盖 | 每个按钮操作有对应的交互页面/弹窗 |
| 字段覆盖 | 列表字段、表单字段与 PRD 字段表格一一对应 |
| 关联改动 | PRD 5.4 关联性改动中的每个改动点都有原型体现 |
| 空状态 | PRD 定义的空状态页面已设计 |

2. 发现遗漏 → 补全页面/组件 → 截图确认
3. 输出覆盖度统计：已覆盖/总数

### 第5轮：最终验收与导出

**关注点**：整体质量终审、导出交付物

**操作**：
1. 全量截图所有页面，逐页终审
2. 检查：

| 检查项 | 通过标准 |
|--------|---------|
| 所有前4轮问题已修复 | 无遗留未修复项 |
| 页面命名规范 | 所有页面使用 P{N}-{页面名称} 格式 |
| 组件库合规 | 100% 使用大禹组件库，无手写组件 |
| 设计规范合规 | 符合 dayu-design-system.md 第15章 |
| 交付完整性 | .pen 文件可正常打开，所有页面可渲染 |

3. 使用 Pencil CLI 导出最终预览图：
   ```bash
   pencil --in "需求/active/{module}/{slug}/07-prototype/prototype.pen" --export "需求/active/{module}/{slug}/07-prototype/assets/preview.png" --export-scale 2
   ```
4. 输出最终迭代报告

## 迭代规则

- 5 轮是标准流程，每轮关注点不同，不可跳过
- 每轮发现的问题必须在当轮修复，不推迟到下一轮
- 如果第5轮仍有重大问题，可追加第6轮，最多不超过6轮
- 每轮修复后必须重新截图确认
