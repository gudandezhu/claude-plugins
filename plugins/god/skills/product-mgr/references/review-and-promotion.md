# 评审与运营宣发规则

## 评审规则

当用户要求评审文档或页面时，自动执行评审。评审分两层：

### 核心层评审标准（所有项目必执行）

按 PRD 核心模块表（8项）的"达标要求"列逐一检查，重点关注含深度要求的模块：

| 检查维度 | 对应模块 | 检查要点 |
|---------|---------|---------|
| 业务差距分析 | M02 | 现状描述具体、目标可量化、差距可追溯到业务场景、改动范围标注类型 |
| 流程完整性 | M07 | 每条主流程有起点→终点，与 M03b E2E 一一对应 |
| 功能业务规则 | M09 | 聚焦业务规则和数据流转，字段含取值规则+边界条件 |
| 异常四维度 | M11 | 数据+操作+权限+环境各至少1条，每条含完整四列 |
| 非功能与验收 | M03b + M13 | 安全/性能/兼容有具体指标值；E2E用具体输入+可判定结果 |

### 适配层评审（按项目配置执行）

具体检查维度和评审标准由适配层定义，可通过在 `$SPEC_DIR` 下放置含"评审"关键字的 .md 文件覆盖。

### 提取AC（验收标准）

**触发**：需求评审通过后，用户说提取AC/生成验收标准/生成ac。

**流程定位**：提取AC发生在「需求评审通过」之后、「角色评审」之前。

**输出**：项目目录下的 `ac.md`（GOAL/AC/UI 三章节结构）。

**质量要求**：AC必须经过质量评审，未通过必须修复后重新评审。具体评审方法和合格标准由适配层定义。

### 评审参数（默认值）

以下参数可通过在 `$SPEC_DIR` 下放置含"评审"关键字的 .md 文件覆盖：

| 类型 | 重点检查项 |
|------|-----------|
| C端页面 | 用户体验、视觉效果、响应式、交互体验 |
| B端系统 | 功能完整性、数据准确性、权限控制 |
| 测试评审 | 测试覆盖率、用例质量 |
| 角色分工 | 各角色评审职责 |

如果 `$SPEC_DIR` 下匹配到含"评审"关键字的 .md 文件，优先使用该文件覆盖上述默认值。

## AC提取参数（默认值）

- **评审方法**：4专家并行评审（PRD覆盖度、可判定性、边界异常、准确性一致性）
- **合格标准**：总分 ≥90/100 且 P0问题 ≤3个
- **重审上限**：最多循环2次

## 运营宣发规则

当用户说生成宣发内容/运营宣发/写更新日志/写功能公告/写帮助文档/出宣发计划时触发。

### 执行流程

```
读取PRD → 功能故事提炼 → 评估功能等级(S/A/B/C) → 生成对应内容资产 → 输出宣发计划
```

### 功能等级评估（4维度，各1-5分）

| 等级 | 总分 | 必须产出 |
|------|------|----------|
| S级 | ≥16 | 故事卡+更新日志+公告+帮助文档+渠道文案+博客+销售话术+宣发计划 |
| A级 | 12-15 | 故事卡+更新日志+公告+帮助文档+渠道文案+销售话术+宣发计划 |
| B级 | 8-11 | 更新日志+公告+帮助文档+宣发计划 |
| C级 | ≤7 | 更新日志 |

内容生成风格和输出路径由适配层定义。

### 内容生成规则

1. **用户语言**：禁止技术术语，面向终端用户
2. **价值导向**：传达用户收益，不是功能描述
3. **数据支撑**：优先使用PRD中的可量化目标
4. **场景化**：从用户日常操作场景出发
5. **行动引导**：每个内容资产必须包含CTA

### 输出路径

内容资产输出到项目目录 `运营宣发/` 下。如果 `$SPEC_DIR` 下匹配到含"宣发"关键字的 .md 文件则按模板生成，否则按内置内容生成规则输出。
