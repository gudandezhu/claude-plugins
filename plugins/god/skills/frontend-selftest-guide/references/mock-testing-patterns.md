# Mock 测试模式

前端自测的核心测试模式。基于 `dev:mock` 模式和 Playwright `page.route` 网络拦截能力。

## 1. Mock 模式检测

启动 dev server 后，通过以下方式确认 Mock 模式生效：
- Network 面板：请求 URL 是否被 mock 拦截（如 MSW 拦截、mockjs 覆盖）
- 控制台：是否有 mock 相关的初始化日志
- 页面数据：列表页是否显示了 mock 数据（非空且格式正确）

Mock 模式不可用时的降级策略：
- 降级为真实后端测试
- 在报告中标注"Mock 不可用，使用真实后端"
- 仍然完成所有验证项

## 2. 查询/加载模式

**场景**：进入列表页、搜索、筛选、分页

验证步骤：
1. 导航到目标页面
2. 验证 Loading 状态（skeleton/spin 出现）
3. 等待数据加载完成
4. 验证 mock 数据正确渲染（表格有行、字段有值）
5. 验证分页控件显示正确（总数、页码）
6. 截图

空数据状态：
- Mock 返回空列表 → 验证空态插图/文案显示
- 验证"新增"按钮仍可用

## 3. 表单提交模式

**场景**：新增、编辑、搜索表单提交

验证步骤：
1. 点击"新增/编辑"按钮 → 验证弹窗/抽屉打开
2. 填写表单字段
3. 点击"提交/保存"按钮
4. 验证 Network 面板发出请求（URL、Method、Body 正确）
5. 验证成功提示（Message.success / Toast）
6. 验证弹窗关闭、列表刷新
7. 截图

## 4. 删除/确认模式

**场景**：删除、状态变更等危险操作

验证步骤：
1. 点击"删除/禁用"按钮
2. 验证二次确认弹窗出现（标题、内容、按钮文案正确）
3. 点击"确认"按钮
4. 验证 Network 面板发出 DELETE/PUT 请求
5. 验证成功提示
6. 验证列表刷新、数据已移除/状态已变更
7. 截图

## 5. 错误模拟模式

**场景**：API 返回错误时的前端处理

使用 Playwright `page.route` 拦截网络模拟错误：

```js
// 拦截指定 API，返回 500 错误
await page.route('**/api/v1/suppliers', route => {
  route.fulfill({ status: 500, body: '{"code":-1,"msg":"服务器错误"}' });
});
```

验证步骤：
1. 设置网络拦截（模拟 500/超时/空响应）
2. 执行操作（提交表单/删除等）
3. 验证错误提示可见（Toast/Alert/Error Message）
4. 验证页面状态不变（弹窗未关闭、表单数据未丢失）
5. 清理网络拦截
6. 截图

关键验证点：
- **错误提示内容**：具体描述了什么错误（非模糊的"操作失败"）
- **数据保留**：表单中已填写的数据不丢失
- **操作可重试**：修复后可再次提交

## 6. 表单校验模式

**场景**：必填校验、格式校验、边界值校验

验证步骤：
1. 打开表单
2. 不填写直接提交 → 验证必填校验提示
3. 输入非法格式 → 验证格式校验提示
4. 输入边界值（超长字符串、特殊字符）→ 验证限制或提示
5. 正确填写后提交 → 验证校验通过
6. 截图每种校验状态

## 7. 状态切换模式

**场景**：Loading / 空数据 / 错误 / 正常 四种状态

| 状态 | 触发方式 | 验证点 |
|------|----------|--------|
| Loading | 刚进入页面/刚触发请求 | skeleton/spin 可见，按钮 disabled |
| 空数据 | Mock 返回空列表 | 空态插图 + 提示文案 |
| 错误 | Mock API 返回错误 | 错误提示 + 重试按钮（如有） |
| 正常 | Mock 返回正常数据 | 数据渲染正确，交互可用 |

每个页面至少验证 Loading + 正常两种状态。
