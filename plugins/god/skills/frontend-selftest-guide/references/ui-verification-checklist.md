# UI 验证清单

精简自 `test-case-design/references/e2e-case-design.md` 覆盖完整性章节。
供 frontend-test subagent 在 Mock 模式下逐条验证。

## 1. 页面渲染（每个页面必做）

- [ ] 无白屏：页面主体内容可见
- [ ] 无控制台错误：F12 Console 无 JS 错误
- [ ] 元素可见：任务文件中定义的所有 UI 元素可见
- [ ] 布局正确：与设计稿无重大偏差
- [ ] 截图留存

## 2. CRUD 操作（涉及增删改查时必做）

### 查询 (Read)
- [ ] 页面加载后列表显示 mock 数据
- [ ] 搜索功能：输入关键词 → 点击查询 → 列表更新
- [ ] 筛选功能：选择筛选条件 → 列表更新
- [ ] 重置功能：点击重置 → 条件清空，恢复默认数据
- [ ] 分页功能：切换页码 → 列表更新

### 新增 (Create)
- [ ] 点击新增按钮 → 弹窗/页面打开
- [ ] 填写表单 → 提交 → 成功提示 → 弹窗关闭 → 列表刷新
- [ ] Network 面板确认请求发出（Method + URL + Body 正确）

### 编辑 (Update)
- [ ] 点击编辑按钮 → 弹窗打开，表单回填数据
- [ ] 修改字段 → 提交 → 成功提示 → 列表刷新
- [ ] Network 面板确认 PUT/PATCH 请求发出

### 删除 (Delete)
- [ ] 点击删除 → 二次确认弹窗
- [ ] 确认删除 → 成功提示 → 列表刷新
- [ ] Network 面板确认 DELETE 请求发出

## 3. 表单校验（涉及表单时必做）

- [ ] 必填字段：不填写直接提交 → 显示校验提示
- [ ] 格式校验：输入错误格式 → 显示格式提示
- [ ] 长度限制：输入超长字符串 → 显示长度提示（或输入被截断）
- [ ] 取消操作：填写一半后取消 → 弹窗关闭，再次打开为空表单

## 4. 错误处理（每个操作至少 1 个错误场景）

- [ ] 模拟 API 500 错误 → 验证错误 Toast/Message 显示
- [ ] 错误后表单数据不丢失
- [ ] 错误后可重新提交（不卡死）
- [ ] 网络超时 → 验证超时提示

## 5. 状态切换（每个页面必做）

- [ ] Loading 状态：数据加载中显示 skeleton/spin
- [ ] 空数据状态：列表为空显示空态插图 + 提示
- [ ] 正常状态：数据正常渲染
- [ ] （可选）错误状态：API 报错后显示错误提示 + 重试

## 6. 边界值（按交互类型选做）

- [ ] 最大输入长度：输入最大字符数 → 验证不溢出
- [ ] 特殊字符：输入 `<script>`、`"`、`'` → 验证无 XSS
- [ ] 并发点击：快速双击提交按钮 → 验证不重复提交
- [ ] 超长列表：Mock 返回 100+ 条数据 → 验证分页正常
