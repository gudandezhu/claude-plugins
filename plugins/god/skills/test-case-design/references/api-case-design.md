# 单 API 接口测试案例设计规范

产出：`{apiCasesOutputPath}`（由主会话展开为绝对路径后传入）
消费方：backend-test（选项 2 生成脚本、选项 3 执行测试）

## 案例格式（强制）

每个案例使用 JSON 格式输出，只写入 .json 文件（不写 .md）。MD 由主会话 json-to-md.js 自动生成。

JSON test_cases 数组中每个条目格式：

```json
{
  "id": "API-{模块}-001",
  "title": "一句话说明验证什么",
  "priority": "P0",
  "type": "happy_path | negative | edge_case | exception",
  "covers": ["AC-XXX"],
  "preconditions": ["前置条件1"],
  "steps": ["具体到请求方法、路径、参数"],
  "expected": ["具体到状态码、响应字段值"],
  "design_method": "AC 驱动",
  "tags": ["标签"]
}
```

异常用例 ID 格式：`API-{模块}-001-E01`，边界用例：`API-{模块}-001-B01`。
version 和 lastUpdatedBy 在 JSON 文件头部声明。

## 覆盖完整性（强制）

每个接口必须包含以下类型的案例：

- 正常请求：每个接口至少 1 个合法参数的正确响应案例
- 参数校验（E 编号）：每个必填参数至少 1 个缺失或类型错误案例，同类型异常可合并
- 边界值（B 编号）：字符串字段最大长度、数值字段边界、空数组、空对象
- 业务规则：唯一性校验、状态流转、关联数据校验（如有）
- 异常场景：未授权、资源不存在、并发冲突、数据库约束违反
- 大数据量边界：超大分页（pageSize=500）、超大金额（9999999.99）、超多明细项（50条）
- 浮点精度：0.1+0.2 类场景，验证金额计算不出现精度丢失
- 接口联动：单 API 案例跳过 CRUD 联动（由 Flow 案例覆盖）。仅在无 Flow 案例时，单 API 案例补充简单的 CRUD 联动验证（创建→查询→修改→删除）

## 与流程案例的边界

| 维度 | 单 API 案例 | 流程案例 |
|------|-----------|---------|
| 关注点 | 单接口的参数校验、边界值 | 多接口串联的业务逻辑 |
| 编号前缀 | API- | FLOW- |
| 消费方 | backend-test | run-test → run-test |
| Mock | 不 Mock | 不 Mock |
| 数据清理前缀 | `API测试_${Date.now()}` | `FLOW测试_${Date.now()}` |

## 覆盖AC 标注（ac.md 存在时）

每条用例的 covers 数组填写对应的 AC 编号（如 ["AC-TAB-01", "UI-STS-01"]）。
ac.md 不存在时 covers 为空数组。

## 禁止事项

- 禁止包含脚本代码片段
- 禁止猜测字段名——标记为"待验证"比猜错更有价值
- 禁止与流程案例混淆——单 API 只关注单接口行为
